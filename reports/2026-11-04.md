## 1. ASR (Automatic Speech Recognition)

### **[BuzzASR: A Swarm of 100+ Monolingual Speech Recognition Models](https://arxiv.org/abs/2609.09554)** (Singh, Yadavalli, Arnett, Warstadt, 2026.09) — EMNLP 2026 Findings
- **arxiv URL**: https://arxiv.org/abs/2609.09554
- **기존 문제**: 다국어 ASR 모델(Whisper 등)은 하나의 모델로 100개 이상의 언어를 처리하지만, 개별 언어에 대한 성능이 전용 모델 대비 떨어지는 문제가 존재. 특히 저자원 언어에서 성능 격차가 큼.
- **기존 방법**: Whisper-large-v3와 같은 단일 다국어 모델이 주류. 언어별 fine-tuning은 시도되었으나 체계적이고 대규모로 수행된 사례가 드물었음.
- **제안 방법**: Whisper를 기반으로 102개 FLEURS 언어 각각에 대해 개별 fine-tuning한 단일언어 모델 군집(swarm)을 구축. 언어별 토크나이저 교체와 텍스트 전용 데이터 증강 기법을 적용.
- **핵심 차별점**: 단일언어 토크나이저 교체로 평균 3.3배 압축률 향상을 달성하며, 대규모 체계적 단일언어 fine-tuning 파이프라인을 제시.
- **실험 결과**: 102개 언어 중 77개에서 Whisper-large-v3를 능가. 평균 CER 2.8배 이상 감소. 27개 언어에서 오픈소스 SOTA 달성 (FLEURS + Common Voice 테스트셋 기준).
- **우리 연구 관련도**: ★☆☆ — fine-tuning 및 토크나이저 최적화 중심으로, prediction-free SSL이나 VQ 기반 표현 학습과는 직접적 관련이 적음.

### **[Token Merging for Multilingual Speech Recognition: A Systematic Study Across Model Scale and Fine-Tuning](https://arxiv.org/abs/2609.13151)** (Holyoak, 2026.07) — arxiv preprint
- **arxiv URL**: https://arxiv.org/abs/2609.13151
- **기존 문제**: Whisper의 오디오 인코더는 상당한 연산 병목을 유발하며, 특히 긴 발화나 실시간 처리 시 효율성이 문제됨.
- **기존 방법**: 모델 경량화(pruning, quantization), knowledge distillation 등의 방법이 있었으나, 인코더 내부의 토큰 수준 중복성을 직접 제거하는 접근은 체계적으로 연구되지 않았음.
- **제안 방법**: Token Merging(ToMe) 기법을 Whisper 모델군에 적용. 인접 토큰을 병합하여 인코더 연산량을 줄이면서 성능 저하를 최소화. 16개 언어, 3가지 모델 스케일, DoRA fine-tuning과의 상호작용까지 체계적으로 평가.
- **핵심 차별점**: 모델 크기에 무관하게 ToMe가 일관되게 적용 가능함을 실증. Fine-tuning과 결합 시에도 WER 저하가 최소화됨을 보여줌 (TRR=0.40에서 최대 +0.59pp WER).
- **실험 결과**: 16개 언어, 3개 Whisper 모델 크기에서 인접 토큰 병합이 WER에 거의 영향을 주지 않음. 저자원 언어(Lingala 등)에서도 성능 저하가 제한적.
- **우리 연구 관련도**: ★☆☆ — 인코더 효율화 연구로, representation learning 자체보다는 추론 최적화에 초점.

### **[Pushing the Boundaries of Streaming Multi-Speaker ASR: A Systematic Study of Architectural Trade-offs](https://arxiv.org/abs/2609.10265)** (Park, Medennikov, Dhawan, Wang, Balam, Ginsburg, 2026.09) — Interspeech 2026
- **arxiv URL**: https://arxiv.org/abs/2609.10265
- **기존 문제**: 다화자 스트리밍 ASR 시스템들이 챌린지 세팅이나 제한된 실험에서만 평가되어, 다양한 아키텍처 간의 포괄적 트레이드오프 분석이 부재.
- **기존 방법**: 다화자 ASR은 주로 SOT(Serialized Output Training), TS-ASR(Target Speaker ASR), 또는 별도 화자분리 후 ASR 파이프라인으로 접근. 각 방법이 개별적으로 연구되어 동일 조건 비교가 어려웠음.
- **제안 방법**: 하나의 공유된 오픈소스 스트리밍 ASR + 화자분리 모델 쌍을 기반으로, 다중 인스턴스 사용 여부와 fine-tuning 여부를 조합하여 4가지 다화자 ASR 시스템을 파생. 동일 조건에서 체계적으로 비교.
- **핵심 차별점**: 다화자 정확도, 단일 화자 성능 저하, 메모리 사용량, 학습 복잡도를 동시에 평가하는 포괄적 프레임워크 제시. 실용적 제약(학습 데이터 부족, 모델 접근 제한, 메모리 제한)을 명시적으로 고려.
- **실험 결과**: 4가지 아키텍처의 트레이드오프를 정량적으로 분석. 구체적 WER 수치는 본문 참조 필요.
- **우리 연구 관련도**: ★☆☆ — ASR 시스템 아키텍처 비교 연구로, representation learning과는 직접적 연관 낮음.

## 2. SpeechLLM (Speech Language Model)

### **[NemotronLabs VoiceChat: An Open Full-duplex Speech-to-Speech Model with Tool Calling Capabilities](https://arxiv.org/abs/2609.21967)** (NVIDIA, 2026.09) — NeurIPS 2026
- **arxiv URL**: https://arxiv.org/abs/2609.21967
- **기존 문제**: Full-duplex 음성 대화 모델들이 대화 능력은 갖추었으나, 외부 도구(API, 검색 등)를 실시간으로 호출하면서 대화를 유지하는 기능이 부재.
- **기존 방법**: 기존 full-duplex 모델(Moshi, LSLM 등)은 음성 생성과 이해에 집중. Tool calling은 텍스트 기반 LLM에서만 성숙한 기능이었으며, 음성 모델에서는 대화 중단 없이 도구를 호출하는 메커니즘이 없었음.
- **제안 방법**: Fast Conformer 음성 인코더 + Nemotron Nano V2 9B LLM 백본 + 독자 TTS 디코더를 결합한 11B 파라미터 오픈 모델. 도구 호출 스크립트를 별도 출력 채널로 분리하여 대화 흐름을 유지하면서 API 호출 가능.
- **핵심 차별점**: 최초의 오픈 웨이트 full-duplex 모델 중 tool calling을 통합한 모델. 대화 중 도구 호출 시 operator 정의 on-hold 메시지로 자연스러운 대화 유지.
- **실험 결과**: Full-Duplex-Bench 3.0에서 tool-selection F1 82.5%. BFCL-v3 spoken tool calling 평균 56.1% (simple 58.5%, multiple 62.5%, parallel 42.5%). 인터럽션 후 takeover rate 100%. 턴테이킹 레이턴시 약 450ms.
- **우리 연구 관련도**: ★★☆ — Full-duplex 아키텍처에서의 speech encoder 활용과 실시간 음성 이해가 speech representation 품질에 의존하므로 간접적 관련성 있음.

### **[A Frontend-Backend Architecture for Tool Calls in Full-Duplex Speech Models](https://arxiv.org/abs/2609.19334)** (Hu et al., 2026.09) — arxiv preprint
- **arxiv URL**: https://arxiv.org/abs/2609.19334
- **기존 문제**: Full-duplex 음성 모델이 도구 호출을 수행하려면 복잡한 추론이 필요하나, 실시간 duplex 모델 단독으로는 정확한 파라미터 추출과 도구 선택이 어려움.
- **기존 방법**: 단일 모델에 tool calling 능력을 직접 학습시키거나(NemotronLabs 등), cascaded 시스템에서 텍스트 LLM이 도구를 호출하되 실시간성을 포기하는 방식.
- **제안 방법**: Frontend(duplex 음성 모델)가 delegation token을 생성하여 스트리밍 ASR 전사를 backend(텍스트 LLM)에 전달. Backend가 도구 호출을 수행하고, 결과를 lightweight prefill-and-repeat 단계로 frontend에 반환하여 TTS로 음성화. 기존 duplex 턴테이킹/바지인 처리를 유지.
- **핵심 차별점**: Duplex 모델의 대화 능력과 대형 텍스트 LLM의 추론 능력을 분리하여 결합. Frontend 수정 최소화.
- **실험 결과**: 단일 턴 도구 호출에서 92-97% tool-call recall, 불필요 호출 거부 정확도 81.2%. Qwen3-235B-A22B 백엔드 사용 시 Full-Duplex-Bench-V3에서 GPT-realtime-mini 및 Qwen3-Omni-30B 능가.
- **우리 연구 관련도**: ★★☆ — Frontend의 스트리밍 ASR 품질이 speech representation에 의존하며, duplex 시스템에서 representation의 실시간 활용 관점에서 참고 가치 있음.

### **[What Did I Just Say? Self-Listening for Full-Duplex Speech Models](https://arxiv.org/abs/2609.05592)** (Zhou, Ao, Liu, Ko, Wang, Li, 2026.09) — arxiv preprint
- **arxiv URL**: https://arxiv.org/abs/2609.05592
- **기존 문제**: Full-duplex 모델에서 텍스트 생성, 음성 합성, 오디오 재생이 비동기적으로 실행되어, 사용자가 인터럽션 전에 실제로 들은 내용과 모델의 내부 상태가 불일치하는 문제 발생.
- **기존 방법**: 기존 full-duplex 모델들은 텍스트 레벨에서 생성 상태를 추적하거나, 인터럽션 시 단순히 생성을 중단하고 새로 시작. 실제 재생된 음성 기반의 상태 동기화는 시도되지 않았음.
- **제안 방법**: Self-Listening — 모델이 실제로 재생한 음성을 입력 스트림으로 다시 피드백하여, 인터럽션 시점에서 사용자가 실제로 들은 내용 기반으로 복구. 인간의 골전도 자기 모니터링에서 영감을 받은 접근법.
- **핵심 차별점**: 텍스트가 아닌 실제 재생된 오디오 기반의 상태 동기화라는 새로운 패러다임. AnchorSpeech 벤치마크 데이터셋도 함께 공개.
- **실험 결과**: Self-listening을 적용한 모델이 기존 full-duplex 베이스라인 대비 더 나은 anchoring 성능을 달성. 구체적 수치는 본문 참조 필요.
- **우리 연구 관련도**: ★★☆ — Self-listening에서 음성 표현의 품질이 자기 모니터링 정확도에 직접 영향을 미치며, speech representation의 실시간 활용 시나리오를 제시.

## 3. Speech Foundation Model

### **[F3-Tokenizer: Taming Audio Autoencoder Latents for Understanding and Generation](https://arxiv.org/abs/2606.06357)** (Zhou, Song, Wu, Cheng, Shen, Lv, 2026.06) — arxiv preprint
- **arxiv URL**: https://arxiv.org/abs/2606.06357
- **기존 문제**: 연속 오디오 오토인코더는 파형 복원에 우수하지만 이해(understanding) 태스크에 약한 latent을 생성. 반면 자기지도 학습 인코더(HuBERT 등)는 의미 정보를 잘 포착하지만 직접 디코딩이 불가능.
- **기존 방법**: 이해와 생성을 위해 별도의 토크나이저를 사용하거나, semantic token과 acoustic token을 계층적으로 결합하는 이중 토크나이저 접근법이 주류.
- **제안 방법**: 연속 오토인코더의 latent을 앵커로 유지하면서, 그 위에 representation encoder를 추가. KL 기반 variational bottleneck 대신 channel normalization + stochastic perturbation으로 스케일 제어된 연속 latent 생성. RQ-MTP와 frozen LLM supervision으로 representation encoder 학습. 생성 측은 patch-level flow head 사용.
- **핵심 차별점**: 하나의 토크나이저로 이해와 생성을 동시에 지원하는 통합 프레임워크. 별도의 semantic/acoustic 분리 없이 단일 latent 공간에서 양쪽 태스크 수행.
- **실험 결과**: ESC-50에서 75.2% 정확도, Seed EN TTS에서 1.88 WER (제3자 집계 기준, 본문 확인 필요).
- **우리 연구 관련도**: ★★★ — 이해와 생성을 통합하는 representation 설계는 VQ 기반 표현 학습 및 speech tokenizer 연구와 직접적으로 관련. Continuous latent 기반 접근은 prediction-free SSL의 대안적 관점 제공.

### **[Dissecting Sensitivity to Training Language in Self-Supervised Speech Learning Using Neural Audio Codec Tokens](https://arxiv.org/abs/2607.26350)** (Takizawa, Nakamura, Cornell, Chen, Fukayama, Watanabe, 2026.07) — arxiv preprint
- **arxiv URL**: https://arxiv.org/abs/2607.26350
- **기존 문제**: 자기지도 음성 학습에서 Neural Audio Codec(NAC) 토큰을 입력으로 사용할 때, NAC 학습 언어와 SSL 사전학습 언어 각각이 다운스트림 성능에 미치는 영향이 분리되어 분석된 적이 없음.
- **기존 방법**: 기존 연구들은 NAC 토큰 기반 SSL을 전체 파이프라인으로 평가했으며, NAC 학습 데이터의 언어와 SSL 사전학습 언어의 개별 기여를 통제 실험으로 분리하지 않았음.
- **제안 방법**: 한 변수(NAC 학습 언어 또는 SSL 사전학습 언어)를 고정하고 다른 변수를 변경하는 통제 실험 설계. 언어별 영향을 체계적으로 분리 분석.
- **핵심 차별점**: NAC 학습 언어는 다운스트림 성능에 거의 영향을 주지 않으나, SSL 사전학습 언어는 큰 영향을 미친다는 핵심 발견. 하나의 NAC를 다국어에 재사용 가능하다는 실용적 시사점 도출.
- **실험 결과**: NAC 학습 언어 변경 시 성능 변화 미미. SSL 사전학습 언어와 타겟 언어의 일치가 성능에 가장 중요한 요인.
- **우리 연구 관련도**: ★★★ — Codec 토큰 기반 SSL의 핵심 설계 변수를 분리 분석한 연구로, VQ 기반 representation learning과 speech tokenizer 설계에 직접적 시사점 제공. Prediction target(codec token)의 특성이 SSL 표현에 미치는 영향 분석.

### **[Do Speech Foundation Models Really Learn Words?](https://arxiv.org/abs/2609.10434)** (Huo, Dunbar, 2026.09) — arxiv preprint
- **arxiv URL**: https://arxiv.org/abs/2609.10434
- **기존 문제**: HuBERT, wav2vec 2.0 등의 음성 기초 모델에서 word-level probe가 성공적으로 작동하지만, 이것이 진정한 단어 수준 표현을 학습한 것인지, 아니면 단순히 음소 정보의 조합에 의한 것인지 불분명.
- **기존 방법**: 기존 probing 연구들은 모델 레이어별 성능을 측정했으나, 음소 수준 정보와 단어 수준 정보를 명시적으로 분리하지 못함. 높은 probe 정확도가 반드시 단어 표현 학습을 의미하는지 검증되지 않았음.
- **제안 방법**: Residualization을 통해 음소 내용을 제거한 후에도 단어 수준 정보가 남아있는지 검증. 레이어별로 음소 인코딩과 단어 인코딩의 단계적 전환을 분석.
- **핵심 차별점**: 후반 레이어에서 국소적 음소 정보에 의존하지 않는 독립적인 단어 수준 표현이 존재함을 실증. 레이어별 단계적 인코딩(음소 → 단어) 패턴 발견.
- **실험 결과**: HuBERT와 wav2vec 2.0의 후반 레이어에서 residualization 후에도 단어 인코딩이 유의미하게 유지됨.
- **우리 연구 관련도**: ★★★ — Self-supervised speech model의 표현이 어떤 수준의 언어 정보를 인코딩하는지에 대한 분석으로, prediction-free SSL 및 temporal contrastive learning에서 목표로 하는 표현 수준 설계에 직접적 참고 가치.
